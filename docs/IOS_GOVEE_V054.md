# ZMF THEATERS+ V0.5.4 — Native iOS lighting and haptics

The iPhone directly controls a *compatible*, powered Govee RGB/RGBIC strip using CoreBluetooth: **no Windows application and no Tapo smart plug are needed** for the light. The app uses the community-reported characteristic 00010203-0405-0607-0809-0a0b0c0d2b11. This proprietary protocol is **not guaranteed** to work with every Govee model. The Windows Home 4DX code and existing YouTube projector stay intact.

Open **Admin → iPhone Govee Lighting**; scan, select a nearby device, choose A/B/C characteristic payload format, send any preview RGB color and visually confirm it worked. Only then enable **Auto-match movie ambience**. Device UUID, selected protocol, brightness, and verification are locally persisted. The driver rediscovers the stored Govee device automatically on app launch while enabled. Do not use unsupported safety-critical, medical, high-power or mains DIY wiring.

**Movie palettes:** On decoded AVPlayer BGRA frames, sample a small central subsampled grid approximately three times per second, avoid black letterbox pixels, calculate a real 24-bit RGB mean, brighten/smooth it, and send color. A bright low-saturation blue/white rink-looking frame maps to soft ice-blue; no object/scene classification or guarantee of semantic “ice rink recognition” is claimed. The 24-bit RGB palette has over 16 million possible numeric colors, although physical hardware may have a smaller gamut and RGBIC segment zones are only controlled if the selected hardware/protocol supports them. No user-picked fixed list. Max 6 BLE command cycles per second, no flash pattern and an explicit 15% minimum brightness.

**YouTube:** WKWebView / YouTube embedded video does **not** provide decoded image pixels. Do not copy protected frames or claim actual scene detection. Use selected cinematic, edits, concert or Minecraft rhythmic palettes driven by the official playback clock and label this fallback in the UI. Web browsing with no movie running sends no colors.

**iPhone haptics:** Continuous Core Haptics engine now updates intensity and sharpness around 40Hz when motion cues update, with a separate 0–100% user strength slider, bounded transients for detected film sound events, and no haptics where the device cannot provide them. This is the iPhone Taptic Engine only, not bHaptics or chair motors.

**Testing:** Unit tests validate checksum, 20-byte BLE payloads for A/B/C, device-name matching, 24-bit RGB, scene palette and interpolated rhythmic transitions. Only a **real iPhone and the actual Govee device** can verify BLE pairing and visible color changes. CI has no physical lights. Bluetooth access requires permission. When iOS suspends the app, continuous ambient synchronization cannot be promised.
